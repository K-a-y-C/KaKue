# Stop preparation or movement and preserve honest outcomes

GitHub issue: https://github.com/K-a-y-C/KaKue/issues/8
Label: ready-for-agent

## What to build

Let Stop terminate preparation, transit or dwell immediately, freeze the current robot pose, and retain every selection with truthful statuses. Handle unexpected failures without fake completion.

**User stories covered:** 26–28, 32 (numbering from the PRD).

This is a vertical slice of the Robot Door Scan Demo: a desktop web app showing the supplied articulated six-axis robot and a fixed door, selecting surface points, simulating verified scanner visits, and downloading PLY/CSV plus unchanged STEP. It is a local-browser simulation; no backend, database, accounts, real scanner/controller, collision planning, or persistence is required.

**Read before implementation:** the complete [PRD](https://github.com/K-a-y-C/KaKue/blob/main/.scratch/robot-door-scan-demo/PRD.md), [agent implementation guide](https://github.com/K-a-y-C/KaKue/blob/main/docs/agents/implementation-guide.md), [robot verification](https://github.com/K-a-y-C/KaKue/blob/main/docs/research/robot-verification.md), and every blocker below. These contain the domain vocabulary, full constants/contracts/state machine, source identity, and acceptance gates; no prior chat context is needed.

**Authoritative assets:** only the user's replacement DOOR-of-CAR.step is the demo door (SHA-256 a2662bda82f6bb30ffd70266ad4fc6398871c36c5d2803f138ef9abd57ef53ef). Ignore all older door inputs; no CATPart conversion remains. The supplied robot STEP must match SHA-256 8b6808af0ca85237dbf5dd73624385ae5fdf36654ef6fd6e4c6cd277683f96a1. Exact local input locations and evidence are in the guide. Source CAD currently exists in the supplied local workspace; confirm it is provisioned in your checkout before asset work. Never silently substitute geometry.

**Implementation conventions:** React/TypeScript/Vite, direct Three.js, local STEP/IK workers and same-origin WASM. Internal meters/radians, UI/export millimeters; right-handed robot-base frame, +Z up, +X toward door. Preserve dimensions and source bytes. Surface points are distinct from stand-off emitter targets. Rendering/FK/IK share the verified RobotDefinition. Use public contracts from the PRD and implement only this ticket's slice; absent future-ticket features are not failures of the current slice.

**TDD:** ONE failing public behavior test → minimal complete implementation → repeat → refactor while green. Favor real browser/integration paths; use independent fixtures/readers for math and exported data. Do not test private component structure, mirror production math as expectations, write all tests upfront, or introduce speculative features. Inspect blocker deliverables, not just ticket state.

## Acceptance criteria

- [ ] Cancellation invalidates the run token; late worker responses and animation callbacks cannot resume or alter cancelled/replaced sessions.
- [ ] Stop disables the laser and preserves visited rows. Moving point becomes stopped, unvisited ready points become not_visited; preparation cancellation retains known diagnostics and otherwise not_visited.
- [ ] Unexpected execution errors enter failed with retained data and available downloads. Imports are disabled during preparation/running; fresh import/reload is recovery.
- [ ] Red–green tests cover Stop during preparation, transit and dwell, late response races and unexpected errors through public run/browser behavior.
- [ ] Record reproducible verification commands/results and deliverable evidence; provide a concise handoff identifying contracts introduced and the next unblocked work. Do not close with unverified mandatory acceptance gates.
